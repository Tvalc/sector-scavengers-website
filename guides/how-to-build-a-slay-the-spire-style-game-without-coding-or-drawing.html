Builder guide

How to build a Slay the Spire style game without coding or drawing

This guide is for creators who want run-based deckbuilding gameplay but do not have a coding or art background. The method is simple: keep first scope tight, test every week, and ship one clear improvement per update.

Practical workflow

  1. Write your loop first. Define hand size, turn economy, loss conditions, and progression rules in one page.
  2. Start with a small card pool. Use a narrow starter set so balance problems show up quickly.
  3. Create encounter pressure. Design fights that force tradeoffs between short-term safety and long-term deck quality.
  4. Track every failed run. Identify where runs break: draw dead zones, economy stalls, or encounter spikes.
  5. Patch weekly. Release one focused improvement and retest with fresh runs.

How to handle art without drawing

Use a style system, not one-off prompts. Keep a character bible, environment bible, and UI vocabulary so every new panel follows the same visual rules. This keeps assets coherent and reduces rework.

See the live examples in the novel pages and the mechanics context on the gameplay section.

Next steps for builders

If your goal is a playable prototype in two weeks, keep your first milestone strict: one character path, one enemy lane, one progression currency, and one reset loop. Then expand content only after your baseline run feels good.
